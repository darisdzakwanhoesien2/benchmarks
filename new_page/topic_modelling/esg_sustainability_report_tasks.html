Phase 1 — Data Preparation
1
Text Preprocessing of Sustainability Report Sections
Tokenization, normalization, and domain-specific cleaning

Perform standard NLP preprocessing on the report_text column extracted from each sustainability report section (e.g., environmental, social, governance). The pipeline must account for bilingual content (English + Bahasa Indonesia) common in Indonesian listed company reports.

Steps
1.1 Cleaning

Remove HTML tags, footnote markers, table artifacts, and page numbers from extracted text

1.2 Normalization

Lowercase all text. Expand common ESG abbreviations (e.g., GHG → greenhouse gas, CSR → corporate social responsibility)

1.3 Stop words

Apply combined EN + ID stop word lists. Add domain-specific stops: "company", "report", "perusahaan", "laporan", "sustainability"

1.4 Lemmatization

Apply spaCy (en_core_web) for English, IndoNLU or PySastrawi for Bahasa Indonesia tokens

1.5 Segmentation

Segment reports into ESG sub-sections (E / S / G pillars) as separate analysis units

1.6 Metadata tagging

Tag each text unit with: company, sector, year, report_pillar, OJK listing tier

Expected output
Cleaned corpus DataFrame Token lists per section Metadata-annotated text units
For bilingual reports, detect language per sentence with langdetect before routing to the correct lemmatizer.

Phase 2 — Lexical and Sentiment Analysis
3
ESG Word Frequency, N-Gram Analysis, and Sentiment Categorization
Term frequency patterns across sentiment categories with word cloud visualization

Define a function to calculate the average sentiment score per report section using multiple sentiment metrics. Categorize each text unit into sentiment bins, then identify the most frequent terms and n-grams per category. This directly extends your existing LLM-based ABSA pipeline.

Sentiment metrics to aggregate
  • afinn_sentiment — lexicon-based valence score
  • bing_sentiment — positive/negative word ratio
  • nrc_sentiment — emotion category distribution (trust, fear, anticipation, etc.)
  • LLM_extracted_sentiment — your thesis pipeline output (κ=0.788 validated)
  • ClimateBERT_score — specialized climate discourse model for comparison
Sentiment bins
Strongly Negative

avg score ≤ −0.6

Moderately Negative

−0.6 to −0.2

Neutral

−0.2 to +0.2

Moderately Positive

+0.2 to +0.6

Strongly Positive

score ≥ +0.6

Outputs
  • Word clouds per sentiment bin — highlight greenwashing risk terms (e.g., "commitment", "strive", "target") in Strongly Positive
  • Top-20 unigrams and bigrams per bin as horizontal bar charts
  • N-gram comparison: E-pillar vs S-pillar vs G-pillar across bins
Greenwashing hypothesis: If Strongly Positive bins show high frequency of vague future-tense commitments ("will achieve", "plans to", "target by 2030") without matching metric disclosures, this is a lexical greenwashing signal.

Phase 3 — Similarity and Clustering
5
Metadata-Based Report Similarity Calculation
Similarity using company characteristics and reporting metadata

Propose and implement a method for calculating similarity between sustainability reports based on company and reporting metadata — analogous to demographic similarity in the original task. This establishes a non-text baseline for comparison with text-based similarity.

Feature set for metadata similarity
  • IDX sector category (one-hot encoded)
  • Company size quartile (market cap)
  • Report year (normalized)
  • OJK listing tier
  • BUMN / private ownership indicator
  • GRI alignment level
  • External assurance: yes/no
Method
  • Encode categorical features; normalize continuous features
  • Compute cosine or Gower distance (handles mixed types) between company-year pairs
  • Produce a pairwise similarity matrix for use in Task 7 clustering
Gower distance is preferred here since it natively handles mixed categorical + continuous features without requiring all features to be binary-encoded first.
6
Text-Based Report Similarity Calculation
TF-IDF, semantic embeddings, and Doc2Vec for content-level similarity

Develop three parallel methods for computing similarity between sustainability report texts. Comparing these three methods reveals different facets of report relatedness and enables boilerplate/greenwashing detection.

TF-IDF Cosine

Sparse representation. High similarity between reports sharing rare ESG terms signals copy-paste boilerplate — a greenwashing indicator

Semantic (SBERT)

sentence-transformers paraphrase-multilingual-mpnet. Captures meaning even when wording differs — critical for bilingual reports

Doc2Vec

Document-level embedding. Track how a single company's vector drifts (or doesn't) across years — static vectors = stagnant ESG narrative

Greenwashing application
  • High TF-IDF similarity across years for same company → boilerplate recycling signal
  • High semantic similarity to industry peers but low actual ESG metric disclosure → isomorphic mimicry signal
  • Doc2Vec vectors stable across years despite claimed ESG progress → narrative stagnation signal
7
Report Clustering Using Metadata and Text Similarities
K-Means, DBSCAN, and Agglomerative Clustering with comparative analysis

Apply clustering algorithms separately to the metadata-based similarity matrix (Task 5) and the text-based similarity matrices (Task 6), then compare the resulting groupings to surface meaningful patterns.

Clustering algorithms
  • K-Means — use elbow method and silhouette score to determine k; best for TF-IDF similarity
  • DBSCAN — density-based; identifies outlier reports that don't conform to any cluster (potential greenwashing anomalies)
  • Agglomerative Clustering — hierarchical; dendrogram reveals sector-level groupings
Comparison analysis
  • Where metadata clusters ≠ text clusters: companies reporting similarly to peers but using very different language — or vice versa
  • Companies that cluster with peers on metadata but are isolated in text space may be genuine ESG leaders or laggards
  • Report report Rand Index / NMI between metadata clusters and text clusters as a quantitative divergence measure
Cluster divergence (metadata vs text) is a novel greenwashing signal contribution: companies that structurally resemble responsible reporters but linguistically differ may be "performative" disclosers.

Phase 5 — Temporal and Entity Analysis
10
ESG Topic Evolution Over Time and Across Companies
Dynamic LDA and BERTopic time-based analysis; longitudinal greenwashing tracking

Track how ESG topics and sentiment evolve over report years for individual companies and sectors. This is the core temporal greenwashing detection component — identifying whether ESG narratives reflect genuine change or superficial recalibration.

Temporal models
  • Dynamic LDA — model topic distribution shifts year over year; detect topics that emerge, persist, or disappear
  • BERTopic with timestamps — topics over time visualization; handles semantic drift in ESG language
  • Rolling sentiment trend — per company, per pillar, across years with statistical trend test (Mann-Kendall)
Cross-entity distributions
  • Topic distribution by sector — which sectors dominate environmental vs governance discourse?
  • Topic distribution by company — identify outlier companies with unusually narrow or broad ESG topic coverage
  • Topic shift after OJK POJK 51/2017 (sustainable finance) mandate — a natural experiment
Greenwashing temporal signals
  • Sentiment increases over time without corresponding disclosure of new metrics → positive sentiment inflation
  • Topic diversity decreases year-over-year despite claimed ESG maturation → topic narrowing signal
  • Sudden positive tone spike in year of regulatory mandate → compliance-driven rather than genuine improvement
OJK's POJK 51/2017 effective from 2020 for all issuers is your strongest natural experiment boundary for before/after analysis.
11
Named Entity Recognition for ESG Content and Commitment Analysis
Identify regulatory bodies, certifications, targets, and co-occurrence networks

Apply NER to sustainability report text to identify and categorize key entities. In this ESG context, named entities are not political figures but regulatory bodies, environmental certifications, policy frameworks, and quantitative commitments.

(a) Entity frequency and sentiment context
  • Entity types: ORG (OJK, BI, PROPER, GRI, CDP), CERT (ISO 14001, ISO 26000, PROPER Emas), POLICY (Paris Agreement, SDG), METRIC (ton CO₂, Rp billion), DATE (target years)
  • For each entity: count appearances in positive vs negative vs neutral sentence contexts
  • Flag entities mentioned only in positive contexts — potential greenwashing signal if paired with vague language
(b) Entity co-occurrence network
  • Build co-occurrence graph: nodes = entities, edge weight = co-occurrence frequency within 50-word windows
  • Visualize with NetworkX + Pyvis: reveal which certification bodies are paired with which policy frameworks
  • Detect "certification clusters" — companies citing multiple certifications together may use them as a credential shield
(c) Cross-feature NER distribution
  • Which sectors most frequently cite OJK / BI regulations? (signal: defensive regulatory framing vs proactive)
  • Are SDG references more common in S-pillar or G-pillar sections?
  • Does external assurance presence correlate with higher metric-entity (METRIC type) density?
Use spaCy with a fine-tuned Indonesian NER model or GLiNER for zero-shot entity extraction. For ESG-specific entities, supplement with a custom entity ruler pattern list.
Phase 6 — Predictive Modeling
12
ESG Sentiment Prediction from Metadata, Text, and Combined Features
Traditional ML + deep learning across three feature configurations

Build sentiment classification models across three feature configurations. Target variable: average composite sentiment score binned into 5 categories (same as Task 3). This tests whether company structure, text, or their combination is most predictive of ESG tone.

(a) Metadata features only
  • Features: sector, company_size, OJK_tier, BUMN flag, GRI alignment, assurance_level, report_year
  • Models: Logistic Regression, Random Forest, XGBoost, TabNet (deep learning for tabular)
  • Evaluate: accuracy, F1-macro, confusion matrix across 5 sentiment bins
(b) Text features only
  • Word2Vec / GloVe embeddings → mean-pooled document vectors → traditional classifiers
  • BERT / IndoBERT fine-tuned for sequence classification on ESG sentiment labels
  • ClimateBERT as a specialized baseline
(c) Combined features
  • Concatenate metadata feature vector + BERT [CLS] token → MLP classifier
  • Compare with late fusion: ensemble metadata model + text model predictions
  • Ablation study: which feature group contributes most to performance improvement?
IndoBERT (indolem/indobert-base-uncased) is recommended for text-only models — it handles Bahasa Indonesia substantially better than multilingual BERT for this domain.
