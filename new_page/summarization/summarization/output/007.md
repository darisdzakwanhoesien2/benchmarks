Section 8. Implementation Blueprint for a Repo-Integrated Benchmark

This section provides a concrete, tool-agnostic blueprint for building and operating a repository-integrated benchmark for Indonesian ESG summarization with ABSA-aware, evidence-grounded capabilities. The blueprint focuses on inputs, artifacts, standardized outputs, experiment tracking, and integration into analysis and writing workflows. It emphasizes reproducibility, governance, and auditability without prescribing specific software stacks.

8.1 Inputs and Artifacts

Overview

The benchmark requires a cohesive set of inputs that represent Indonesian ESG disclosures, their OCR-processed text, auxiliary evidence, and meta-information. All inputs should be versioned and timestamped to support traceability and auditability.
8.1.1 Source documents and preprocessed text

Source documents: A corpus of ESG disclosures (annual reports, sustainability reports, governance memos, assurance letters) from IDX-listed Indonesian firms, spanning multiple years.
Raw OCR outputs: Text extracted from scanned PDFs or image-based sources, including document-level metadata (page numbers, column structure, table boundaries).
OCR quality signals: Per-passages confidence scores, bounding-box information, and layout metadata to support downstream grounding and error handling.
Cleaned text: Preprocessed plain text with normalization (case, diacritics), language tagging (Indonesian vs. English segments), and basic de-noising (removal of obvious artifacts).
8.1.2 Ground-truth and reference materials

Expert-authored reference summaries (record-, company-, and year-level) aligned to ESG pillars and with explicit provenance.
Ground-truth evidence mappings linking claims to primary sources (tables, KPI figures, policy clauses, board minutes).
Regulatory references and standard mappings (GRI, POJK, SPOTT, etc.) used to contextualize claims.
8.1.3 ABSA signals and metadata

Aspect- and pillar-tagged annotations derived from ABSA pipelines, including: aspectlabel (e.g., Environment: emissions intensity), sentimentlabel (positive/neutral/negative), confidence_score, and provenance links to source sentences.
Content-plan anchors: derived from ABSA outputs indicating required summary elements and corresponding evidence.
8.1.4 Evaluation and ground-truth tooling

Evaluation scripts and configuration for ROUGE, semantic metrics, and faithfulness checks.
NLI/QA model prompts or templates (for faithfulness evaluation) and corresponding ground-truth answer keys where available.
Human-annotation guidelines and scoring rubrics for faithfulness, coverage, usefulness, and auditability.
8.1.5 Metadata and provenance schemas

A unified schema for provenance, pillar/aspect coverage, units/baselines, and tone commitments to support traceability in all outputs.
A citation ledger structure that records exact source passages, document identifiers, and positions.
8.2 Standardized Outputs

Output taxonomy

Summary units are generated in pillar-aware, modular forms and assembled into higher-level narratives as needed. All outputs carry explicit provenance and evidence anchors.
8.2.1 File naming conventions (examples)

Source and processing:
data/raw/{documentid}/{year}/rawtext.txt
data/ocr/{documentid}/{year}/ocrmetadata.json
data/tableextractions/{documentid}/{year}/tables.json
Summaries and plans:
results/summaries/{companyid}/{year}/recordlevel_summary.txt
results/summaries/{companyid}/{year}/companylevel_summary.txt
results/summaries/comparatives/{year1}-{year2}/{industry_segment}.txt
results/ABSAplans/{documentid}.json
Evidence and grounding:
grounding/{claim_id}.json (with provenance per claim)
grounding/{document_id}/{year}/citations.csv
Faithfulness and evaluation:
faithfulnessaudit/{documentid}/{year}/audit.csv
faithfulnessaudit/{documentid}/{year}/questions_answers.json
Benchmarks and dashboards:
dashboards/{benchmarkrunid}/overview.html
dashboards/{benchmarkrunid}/pillars.csv
Model artifacts and configs:
models/{strategy}/{document_id}/config.json
models/{strategy}/{document_id}/weights.bin
Data cleaning and preprocessing logs:
logs/cleaning/{document_id}.log
Reproducibility artifacts:
experiments/{experiment_id}/readme.md
experiments/{experiment_id}/seed.txt
8.2.2 Summary unit metadata (example schema)

provenance:
documentid, year, sourcesection, tableid, rowid, column_id, page
pillar_coverage: Environment, Social, Governance
aspect_label: e.g., "GHG emissions intensity"
sub_aspect: optional (e.g., "Scope 1 emissions")
KPIdetails: metricname, unit, baseline, target, year
tonecommitmentdistribution: e.g., {"Environment": 0.6, "Governance": 0.3, "Social": 0.1}
evidenceanchor: citationid or sourcepassageid
confidence: ABSA or grounding confidence score
format: record-level / company-level / comparative / chapter-ready
8.2.3 Grounding and citations

A dedicated grounding file per claim linking to one or more source fragments, including:
sourcedocumentid, year, fragmenttype (table, paragraph, figure), locationspec (e.g., page, row, column), and a short quote (if permitted).
A citation ledger that maps each claim to its exact source passage identifiers and confidence.
8.3 Experiment Tracking

Principles

Track experiments end-to-end with versioned data, code, seeds, and randomization controls to ensure replicability and auditability.
8.3.1 Tracking essentials

Experiment metadata: experimentid, date, researcher, datasetversion, model_version, hyperparameters, evaluation metrics, checkpoint locations.
Reproducibility artifacts: links to code commits, container/image tags (if used), and environment specifications (language, libraries, CUDA, etc.).
8.3.2 Suggested experiment logging structure (example)

experiments/{experimentid}/experiment.json
fields: id, timestamp, description, dataset
version, modelversion, strategy, seed, OCRpreprocessingconfig, metricssummary, anchorcoverage, groundtruthmatch, noveltyscore
experiments/{experimentid}/metrics.csv
columns: document
id, year, ROUGE-1, ROUGE-2, ROUGE-L, BERTScore, groundingprecision, groundingrecall, faithfulnessscore, timeto_generate
experiments/{experiment_id}/predictions/
per-document folders containing summaries, ABSA plans, and grounding files
experiments/{experiment_id}/plots/
per-metric visualizations and dashboard exports
8.3.3 Versioning and governance

Use semantic versioning for data and model releases (e.g., v1.0.0 for dataset, v1.0.0 for model).
Maintain a changelog describing data corrections, OCR-cleaning policy updates, and evaluation schema changes.
Enforce access controls and audit trails for provenance and evaluation results.
8.4 Integration into Analysis and Writing

8.4.1 Analysis workflow integration

A modular pipeline design that connects inputs → ABSA planning → summarization (extractive, constrained abstractive, or hybrid) → grounding and citation enrichment → faithfulness checks → evaluation metrics → dashboards.
Automated reporting: Generate a narrative section draft that reflects ABSA-informed content plans, with explicit pillars and cited sources, ready for editorial review.
8.4.2 Writing workflow integration

Outputs can be consumed by drafting tools to assemble ESG chapters. The summary units (record-level, company-level, comparative, chapter-ready) inform the structure of each chapter, while provenance and grounding metadata enable editorial checks and regulator-facing appendices.
8.4.3 Validation and governance

Establish a standard validation step: before finalizing a summary, confirm that all claims have explicit citations and that key KPIs align with source tables.
Maintain an evidence appendix: a machine-readable ledger of all claims and their supporting passages to support external audits or regulatory inquiries.
8.4.4 Interoperability and extensibility

Design data schemas and outputs to be compatible with common data science tooling, journaling platforms, and document authoring pipelines without locking into a single stack.
Provide hooks for future enhancements: new ABSA signals, additional pillars, or expanded types of evidence (e.g., supplier certifications).
8.4.5 Example end-to-end run (high-level)

Ingest ESG disclosures for Company A (years 2021–2023) with OCR text
Run a domain-specific ABSA pass to identify aspects, sentiments, and provenance
Generate multiple outputs according to the three strategies (extractive, constrained abstractive, hybrid)
Ground claims to source passages; produce evidence ledger
Execute faithfulness checks (NLI/QA/classifiers) and collect human audit samples
Compile evaluation metrics (ROUGE, semantic similarity, grounding accuracy, faithfulness scores)
Update dashboards with pillar-wise summaries, grounding density, and cross-year trends
Produce Chapter-ready narrative with an evidence appendix for investor/regulatory review
Notes on tool-agnosticism

The blueprint intentionally avoids prescribing specific toolchains. It emphasizes data shapes, file structures, and metadata workflows so teams can implement with their preferred libraries and platforms while preserving interoperability and auditability.
