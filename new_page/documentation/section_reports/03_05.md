# 3.5 Metrics Definition

## Section Purpose

This section defines the methodological foundation for the ESG disclosure tone analysis pipeline. The design follows a mixed-method research logic because the project combines document engineering, NLP model experimentation, LLM-based information extraction, and interpretive evaluation of disclosure tone. Prior work on corporate disclosure, sustainability reporting, ESG analytics, climate disclosure mining, ABSA, and machine-learning-based ESG research supports this integrated design [R012], [R026], [R027], [R033], [R056].

## Research Positioning

The pipeline is exploratory rather than purely confirmatory. The current workspace does not yet contain a complete expert-labeled ground-truth dataset, so the research cannot honestly claim final supervised classification validity. Instead, the methodology treats model outputs, ClimateBERT-style labels, ontology mappings, and manually inspectable records as triangulated evidence. This is appropriate for an early-stage ESG text-mining study where the first objective is to build a reproducible research instrument and identify where future annotation should focus.

The methodological unit of analysis is the ESG disclosure record. A record may come from a sentence, paragraph, table fragment, or page batch. Each record stores text, ESG pillar, aspect, tone, sentiment, labels, reasoning, source target, prompt, and model metadata. This structure allows the research to move beyond document-level ESG scoring toward evidence-level interpretation.

## Operational Design

The design uses four linked operations:

1. Convert sustainability reports into markdown through OCR and page-level processing.
2. Extract structured ESG records using LLM prompts.
3. Compare record-level tone against ClimateBERT-style climate labels and ABSA outputs.
4. Visualize and document the resulting patterns for auditability.

The current empirical snapshot includes 332 extracted ESG records from 110 successful ESG extraction runs, using 7 prompt templates and 2 LLM backends/models. The tone distribution is `commitment`=115, `missing`=61, `action`=58, `outcome`=50, `none`=48. These figures are used as methodological evidence of feasibility, not as final population estimates.

## Rationale

A single-method design would be too narrow for this topic. Manual ESG scoring is interpretable but slow; pure LLM extraction is flexible but schema-sensitive; ClimateBERT is strong for climate-related signals but does not directly classify commitment, action, and outcome; rule-based ABSA is transparent but brittle. Combining these methods creates a defensible research design: each layer compensates for a weakness in the others.

The use of multiple prompt templates is also methodological rather than incidental. Zero-shot prompts measure direct instruction-following, few-shot prompts test whether examples stabilize schema behavior, and chain-of-thought style prompts test whether reasoning-oriented instructions improve classification detail. English and Indonesian variants reflect the bilingual nature of the reports.

## Validity Controls

The design uses transparency controls: raw outputs are preserved, parsed records are saved in JSON, visualizations can be regenerated, and the Streamlit dashboard allows filtering by tone, ESG pillar, source document, and prompt. The main validity limitation is that weak labels and model-derived labels cannot replace expert annotation. Therefore, this section recommends treating the current pipeline as a benchmark-construction apparatus.

## Expected Output

The expected output of this methodological section is a clear explanation of how the pipeline transforms reports into structured evidence and how that evidence can later support formal evaluation. The section should be read alongside `results/esg_records.json`, `results/climatebert_results.json`, and the generated visualization tables.

## Section-Specific Report

Metrics are defined at five levels. OCR metrics include page coverage, successful document conversion, extracted image count, and future character/table accuracy measures. Extraction metrics include JSON parse success, record count per run, field completion rate, missing tone rate, and schema drift rate.

ABSA metrics should eventually include aspect precision, recall, and F1 once expert labels are available. At the current stage, ABSA outputs are used mainly for comparison and diagnosis. Ontology alignment is interpreted as the semantic consistency between extracted text and ESG ontology paths.

Cross-model agreement measures whether rule-based, ML, hybrid, LLM, and ClimateBERT-style outputs converge. The greenwashing index is defined heuristically as a commitment-to-outcome imbalance per document or target. A higher commitment/outcome ratio may indicate that disclosure emphasizes promises more than demonstrated results, but this requires validation against expert labels or external ESG assessments.
