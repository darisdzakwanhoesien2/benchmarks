# 4.5 Explainability Outputs

## Section Purpose

This section reports the implementation and empirical outputs produced by the ESG disclosure analysis pipeline. It connects the research questions to concrete artifacts, including JSON result files, CSV summaries, static charts, and the Streamlit dashboard. The implementation reflects recent literature on ESG data analytics, sustainability report mining, climate disclosure NLP, LLM-based disclosure tools, and explainable AI [R014], [R019], [R038], [R054], [R061].

## Implementation Context

The implemented system is a Python and Streamlit multi-page application. It organizes source documents under `data/`, processing pages under `pages/`, analytical modules under `code/`, prompt templates under `prompt/`, experiment outputs under `results/`, and documentation under `docs/` and `documentation/`. The central empirical artifact for this report is `results/esg_records.json`.

The current extraction file contains 110 successful ESG extraction runs and 332 extracted ESG records. The records were produced by 7 prompt templates and 2 LLM backends/models. The results demonstrate that PDF-derived sustainability disclosure can be transformed into structured ESG evidence with fields for text, aspect, labels, ESG pillar, sentiment, tone, and reasoning.

## Results Summary

The tone distribution is `commitment`=115, `missing`=61, `action`=58, `outcome`=50, `none`=48. The ESG pillar distribution is `E`=179, `G`=121, `none`=27, `S`=4, `missing`=1. The most important ClimateBERT-style validation pattern is `commitment` with `climate-commitment`=91, `climate-d`=57, and `environmental-claims`=48. This alignment is valuable because it suggests that many future-oriented ESG statements were also recognized by climate-related labels as commitment-like or environmental-claim-like.

At the same time, the results reveal quality issues. There are 61 missing tone records. The sentiment field also contains schema drift, including 18 records where `commitment` appears as sentiment. Social-pillar records are underrepresented with only four records. These weaknesses are not failures of the research design; they are diagnostic findings that show where annotation and prompt refinement should be targeted.

## Interpretation

The implementation confirms the feasibility of automated tone-aware ESG disclosure analysis. It also shows why visualization is essential. Aggregate counts reveal the dominance of commitment-oriented disclosure, while heatmaps reveal whether those commitments correspond to climate-related labels or appear as ambiguous/missing records. The dashboard therefore functions as both an analytical instrument and a quality-control interface.

## Reproducibility

The static artifacts can be regenerated with:

```bash
python3 code/visualize_tone_climatebert.py
```

The Streamlit dashboard can be launched with:

```bash
streamlit run app.py --server.port 8590
```

This reproducibility design supports transparent reporting and future extension.

## Section-Specific Report

Explainability is implemented through several mechanisms. Rule-based outputs expose lexical triggers, such as commitment markers (`will`, `target`, `committed`), action markers (`implemented`, `conducted`, `established`), and outcome markers (`achieved`, `reduced`, `completed`). Classical ML outputs can expose TF-IDF coefficients that show which terms contribute most strongly to aspect, sentiment, or tone predictions.

Ontology-aware outputs map records to ESG paths, helping users understand whether a statement is environmental, social, governance, or generic. Section influence can be inspected by comparing where disclosures appear in the report. Representative examples should include text, predicted tone, ESG pillar, ClimateBERT-style labels, and reasoning so reviewers can evaluate whether the model's classification is plausible.
